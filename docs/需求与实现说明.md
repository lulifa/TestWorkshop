## 2. 项目背景与目标

### 2.1 业务背景

TestWorkshop 面向船用液压产品的车间测试业务。测试台在实际测试过程中产生实时运行数据和测试曲线数据，车间人员需要围绕测试订单完成设备准备、测试执行、数据归集、异常发现和结果审核。

当前业务需要解决以下问题：

- 车间、设备和测试订单缺少统一管理入口。
- 测试订单执行状态和测试台占用关系需要明确控制。
- 下位机实时数据与测试结束后上传的图谱数据需要分类管理。
- 不同设备类型的测试阈值需要统一配置。
- 测试过程中出现的超限、设备异常和通信中断需要及时发现。
- 订单测试结果需要进入审核流程，并支持报告查看和最终报告下载。
- 用户、角色、车间数据范围和业务操作权限需要清晰隔离。

### 2.2 产品目标

平台应实现以下业务目标：

1. 建立“车间 → 测试台 → 测试订单 → 测试数据 → 报警 → 审核结果”的完整业务链路。
2. 支持多车间、多设备类型的日常测试管理。
3. 支持测试台实时数据接收、在线状态判断和即时报警。
4. 支持测试完成后上传或归集波形图谱数据，并在订单中查看。
5. 支持按设备类型配置阈值，并按阈值自动判断异常。
6. 支持质量审核员对测试报告进行审核，审核通过后开放最终报告下载。
7. 支持消息、通告、日志和数据保留等日常运营管理能力。

### 2.3 业务模块实现逻辑总览

| 业务模块 | 模块定位 | 主要触发方式 | 核心业务实现逻辑 | 业务输出 |
| --- | --- | --- | --- | --- |
| 登录与权限 | 确认当前用户身份和可操作范围 | 用户登录、访问页面、执行操作 | 用户登录后识别角色和所属车间；菜单按角色展示；具体业务操作再次校验角色和数据范围 | 可用菜单、可用操作和受限数据范围 |
| 工作台 | 汇总当前用户最常用的信息 | 用户登录后进入工作台 | 聚合天气、常用菜单、消息、通告和待办；当前待办暂未接入真实数据 | 日常业务入口和待处理信息 |
| 实时监控 | 查看当前在线测试台状态 | 用户打开实时监控或等待自动刷新 | 根据心跳判断在线；读取最新实时指标；按车间分组展示 | 在线设备、实时指标、运行时长和最新数据时间 |
| 车间与人员 | 建立业务数据归属和车间账号体系 | 管理员新增车间、初始化人员 | 创建车间组织并写入业务编码；按命名规则开通车间主管、大区负责人和测试工程师账号 | 车间组织、人员账号和角色归属 |
| 测试台设备 | 管理测试对象和执行设备 | 管理员维护设备；下位机上报心跳 | 设备绑定车间和类型；心跳更新在线状态和累计运行时长；设备和订单按车间控制可见范围 | 可用测试台清单和设备状态 |
| 测试订单 | 承接触发一次完整测试任务 | 调度或管理员创建订单；车间人员执行测试 | 订单按状态机流转；开始测试时占用测试台；结束或取消后释放；按角色和车间控制操作权 | 测试任务状态、测试时间和订单过程记录 |
| 测试报告 | 对测试结果进行归档和审核 | 订单测试完成、报告就绪、审核员审核 | 获取并保存订单报告文件；审核员查看报告并给出通过或不通过；审核通过后锁定并开放下载 | 报告文件、审核记录和最终下载包 |
| 阈值管理 | 定义不同设备类型的正常范围 | 管理员维护设备类型阈值 | 按设备类型和物理量保存上下限；实时数据进入报警判断时读取对应阈值 | 可供报警判断使用的阈值规则 |
| 实时数据 | 反映测试台当前运行状态 | 下位机持续推送测试台数据 | 校验设备编码，归一化物理量，保存最新帧；同一设备同一时间的数据覆盖旧值 | 当前压力、流量、温度、扭矩、振动和急停状态 |
| 图谱数据 | 保存测试过程曲线和被测产品信息 | 下位机上传 CSV 和测试参数 | 创建处理任务；解析采样点；根据测试时间匹配订单；保存为按通道组织的波形数据 | 订单图谱、任务记录和被测产品信息 |
| 报警管理 | 发现测试过程中的异常状态 | 实时数据、急停或心跳满足异常条件 | 按最新数据即时判断；同一异常只保留一个进行中报警；条件恢复后关闭报警；所有用户可查看 | 进行中/已恢复报警和处理依据 |
| 消息与通告 | 传递订单通知和平台信息 | 订单创建、管理员发送消息或通告 | 普通消息按接收人保存；通告面向全部用户；在线用户实时提醒；已读状态按用户维护 | 我的消息、我的通告和实时提醒 |
| 平台管理 | 维护业务运行所需的基础配置 | 管理员进入平台管理 | 管理遥测任务、阈值、文件、菜单、布局、字典、消息和通告 | 可支撑业务运行的基础数据和配置 |
| 系统管理 | 维护用户、权限和组织体系 | 管理员进入系统管理 | 管理用户、角色、权限和组织；记录审计和安全日志；管理租户 | 账号权限体系、组织体系和操作记录 |

## 3. 业务术语

| 术语 | 说明 |
| --- | --- |
| 车间 | 设备、人员和订单的主要业务归属单位 |
| 测试台 | 执行产品测试的设备，实时数据和心跳均按测试台归集 |
| 被测设备 | 被测试的液压产品或部件；与测试台不是同一概念 |
| 测试订单 | 一次测试任务的业务载体，关联一台测试台和一个单船项目主管 |
| 实时数据 | 测试台按约定周期推送的当前运行指标 |
| 图谱数据 | 测试结束后按通道上传的波形采样数据 |
| 阈值 | 按设备类型和物理量配置的正常范围 |
| 报警 | 实时值异常、测试台急停或通信中断等异常状态 |
| 测试报告 | 订单测试完成后供质量审核员查看、审核和归档的结果文件 |
| 单船项目主管 | 对某一订单负责的全局岗位人员 |

## 4. 用户角色与职责

### 4.1 角色定义

| 角色 | 组织关系 | 主要职责 |
| --- | --- | --- |
| 管理员 | 全局 | 管理用户、权限、车间、设备、订单、阈值和平台配置 |
| 车间主管 | 隶属一个车间 | 管理本车间测试过程，开始、结束或取消测试订单 |
| 测试工程师 | 隶属一个车间 | 执行本车间测试任务 |
| 大区负责人 | 隶属一个车间 | 查看本车间业务并接收新订单通知 |
| 调度 | 全局岗位 | 跨车间创建、编辑、删除和跟踪测试订单 |
| 单船项目主管 | 全局岗位 | 查看和下载本人负责订单的相关信息 |
| 质量审核员 | 全局岗位 | 查看全部订单，审核测试报告并下载最终报告 |
| 访客 | 全局或受限 | 在授权范围内只读查看业务信息 |

### 4.2 用户与组织要求

- 每个车间在系统中应有独立的组织节点和业务编码。
- 车间主管、测试工程师和大区负责人应隶属对应车间。
- 调度、单船项目主管和质量审核员为全局岗位，不强制隶属某个车间。
- 新车间开通时，应支持同时初始化车间主管、大区负责人和测试工程师账号。
- 同一车间下可配置多个用户，角色不可替代数据归属关系。

## 5. 数据可见范围

### 5.1 总体原则

- 设备和订单默认按用户所属车间控制可见范围。
- 管理员不受车间范围限制。
- 调度和质量审核员因岗位职责需要，可查看全部订单。

## 7. 核心业务流程

### 7.1 车间和测试台开通

1. 管理员创建车间组织，填写车间名称和业务编码。
2. 可选择同时初始化该车间的车间主管、大区负责人和测试工程师账号。
3. 管理员为车间配置测试台设备。
4. 测试台启用后，下位机开始上报心跳和实时数据。
5. 车间人员登录后只能看到所属车间的设备和订单。

### 7.2 测试订单执行流程

```text
创建订单
  ↓
已录入未测试
  ↓
开始测试
  ↓
测试中
  ↓
结束测试
  ↓
测试完成待审核
  ↓
报告审核
  ├─ 审核通过 → 最终报告可下载
  └─ 审核不通过 → 可重新审核
```

取消规则：

- 已录入未测试的订单可以取消。
- 测试中的订单可以取消，取消后释放测试台。
- 已进入待审核、审核通过或审核不通过的订单不能取消。

### 7.3 测试执行与数据归集流程

1. 车间主管或测试工程师开始测试，订单进入测试中状态。
2. 测试台开始持续推送实时运行指标和心跳。
3. 系统按阈值即时判断异常并形成报警。
4. 测试结束后，订单进入待审核状态。
5. 下位机上传或由系统归集本次测试的图谱数据。
6. 系统根据测试时间将图谱数据关联到对应订单。
7. 无法唯一关联订单的图谱数据保留为“未关联订单”状态，供人工核查。

### 7.4 报警处理流程

1. 系统读取测试台最新实时数据或心跳状态。
2. 当前值超过阈值、发生急停或心跳超时后，报警即时成立。
3. 报警显示在报警列表中，所有登录用户均可查看。
4. 后续数据恢复正常或心跳恢复后，报警自动恢复。
5. 数据停止上报时，已有数据类报警不会自动恢复。
6. 报警不发送站内消息，不进行人员升级通知。

### 7.5 测试报告审核流程

> 当前状态：报告审核、预览和下载界面已预留，真实测试报告获取尚未实现，因此本条流程暂不能完整上线使用。

1. 订单测试结束后进入待审核状态。
2. 系统获取该订单的测试报告文件。
3. 报告就绪后，质量审核员可查看报告文件。
4. 审核员选择审核通过或不通过，并可填写维保建议。
5. 审核不通过时，保留历史审核记录，允许重新审核。
6. 审核通过后，订单锁定，不再允许重新审核。
7. 审核通过且报告存在时，有权限用户可下载最终报告。

## 8. 功能需求

### 8.1 登录与个人中心

**模块定位**：确认登录用户身份，并让用户维护自己的基础资料和账户安全信息。  
**实现逻辑**：用户完成登录后，系统识别其角色、所属车间和权限；页面据此展示可用菜单和操作。用户进入个人中心后可维护资料、密码和头像。

#### 8.1.1 登录

- 用户可通过系统登录页完成身份认证。
- 登录后按角色和权限展示可用菜单和操作。
- 登录失效时应提示重新登录。
- 系统应支持个人资料、修改密码和头像管理。

#### 8.1.2 个人中心

- 查看和编辑个人基本资料。
- 修改登录密码。
- 上传和更新头像。
- 查看账户安全相关信息。

---

### 8.2 工作台

**模块定位**：为登录用户提供一个汇总业务入口和待处理信息的首页。  
**实现逻辑**：系统聚合天气、常用菜单、最近消息、最新通告和待办信息。常用菜单按用户收藏维护，消息和通告按当前用户已读状态展示。

#### 8.2.1 欢迎与天气

- 根据登录用户展示欢迎信息。
- 展示天气信息；天气服务不可用时应降级展示，不影响工作台使用。

#### 8.2.2 常用菜单

- 用户可添加常用菜单。
- 用户可删除不再使用的常用菜单。
- 点击常用菜单可跳转到对应业务页面。

#### 8.2.3 消息与通告

- 展示未读消息和最新通告。
- 支持跳转到“我的消息”和“我的通告”。

#### 8.2.4 待办事项

- 工作台预留待办事项区域。
- 当前版本待办列表为空，尚未接入业务数据。
- 后续应明确待办来源、优先级、完成状态和跳转规则。

---

### 8.3 实时监控

**模块定位**：让用户快速了解当前有哪些测试台在线、正在显示什么指标以及已经运行多久。  
**实现逻辑**：系统先根据最后心跳判断设备是否在线，再读取每台在线设备的最新实时数据，按车间分组展示，并按固定周期刷新页面。

#### 8.3.1 展示内容

- 展示当前在线测试台。
- 按车间对测试台进行分组。
- 展示测试台名称、设备编码、设备类型和所属车间。
- 展示压力、流量、温度三个实时指标。
- 展示累计在线时长、最后心跳时间和最新数据时间。

#### 8.3.2 查询与筛选

- 支持按车间筛选。
- 支持按设备名称或设备编码搜索。
- 支持手动刷新。
- 页面应自动刷新，默认刷新周期为 60 秒。

#### 8.3.3 在线判断

- 最后一次心跳距当前时间小于通信超时阈值的设备视为在线。
- 当前通信超时阈值为 10 秒。
- 超过阈值的设备不再显示为在线设备。

#### 8.3.4 实时性说明

- 下位机可持续上报实时数据。
- 当前实时监控页面采用周期刷新方式展示最新状态，不等同于页面实时推送。
- 如后续要求页面秒级刷新，应另行明确刷新频率和性能要求。

### 8.6 测试订单管理

**实现逻辑**：订单创建后按状态机流转；开始测试时检查测试台是否已被占用并锁定设备；结束或取消后释放设备；查询详情、审核记录、任务和图谱时继续校验订单可见范围。

#### 8.6.1 订单信息

| 信息项 | 是否必填 | 规则 |

#### 8.6.2 订单查询

#### 8.6.3 订单状态

| 状态 | 含义 | 可执行操作 |

### 8.7 测试报告

> 当前状态：未完成。以下内容作为后续建设需求，不应描述为已交付功能。

**模块定位**：为测试订单提供正式结果文件，并支撑质量审核、结果确认和最终归档。  
**目标实现逻辑**：订单进入待审核后获取报告文件，报告就绪后由审核员查看并给出审核结论；审核通过后锁定订单并按权限开放报告下载。

#### 8.7.1 报告来源

- 测试报告由外部测试或报告系统生成并提供。
- 平台按订单信息获取该订单对应的报告文件。
- 获取方式、鉴权方式、文件格式和“暂无报告”返回规则需由外部系统明确。

#### 8.7.2 报告状态

| 状态 | 含义 |
| --- | --- |
| 未获取 | 尚未取得报告 |
| 获取中 | 正在从外部系统获取报告 |
| 已就绪 | 报告文件已取得，可审核 |
| 获取失败 | 获取过程中发生错误 |
| 已过期 | 报告文件超过保留期并已清理 |

#### 8.7.3 报告文件

- 一个订单可以包含多个报告文件。
- 文件应记录名称、大小、类型和生成时间。
- 系统应校验文件是否完整、是否超过大小限制。
- 同一订单重新获取报告时，应明确覆盖旧文件还是保留历史版本。

#### 8.7.4 报告获取

- 系统可在订单进入待审核后自动获取报告。
- 有权限人员可手动触发获取。
- 自动获取默认每 60 秒检查一次待获取订单。
- 测试结束后默认最多在 30 天内自动获取报告。
- 获取失败应支持重试。
- 首次失败默认等待 300 秒后重试，后续按指数退避，单次等待最长 3600 秒。
- 同一订单默认最多尝试 60 次。
- 获取中的请求不应重复创建。
- 长时间处于获取中的请求应可自动恢复。
- 报告获取过程应保留记录，至少包含触发方式、请求时间、结果和失败原因。

#### 8.7.5 报告预览

- 有订单查看权限的用户可在审核抽屉中查看报告文件。
- 支持在多文件之间切换。
- PDF 当前仅预览第 1 页。
- 文本类文件当前仅展示前 30% 内容。
- 不支持浏览器预览的文件应明确提示下载查看。

#### 8.7.6 报告审核

- 管理员和质量审核员可执行审核。
- 审核结果包括通过和不通过。
- 审核时可填写维保建议。
- 审核时必须存在可用的报告文件。
- 审核不通过后允许再次审核。
- 审核通过后不再允许重新审核。
- 每次审核追加记录，不覆盖历史审核结果。
- 审核记录应保存审核结果、审核人、审核时间、维保建议和报告文件数量。

#### 8.7.7 报告下载

- 只有审核通过的订单可下载最终报告。
- 管理员、质量审核员和调度可下载全部已审核通过的订单报告。
- 单船项目主管只能下载本人负责订单的报告。
- 一个订单存在多个报告文件时，应打包为一个 ZIP 文件下载。
- ZIP 文件命名格式为 `订单号-测试报告.zip`。

#### 8.7.8 报告保留

- 报告文件默认保留 1095 天。
- 同一订单的全部报告文件到期后，报告状态变为“已过期”。
- 过期文件应从文件存储中清理。
- 清理失败应记录并支持后续重试。

### 8.8 阈值管理

**模块定位**：定义不同设备类型在不同物理量上的正常范围，为报警判断提供业务依据。  
**实现逻辑**：管理员按设备类型维护 5 个物理量的上下限和启用状态；系统保存时校验上下限关系；实时数据判断报警时读取该设备类型对应的启用规则。

#### 8.8.1 物理量范围

平台固定管理以下 5 个物理量：

| 物理量 | 单位 |
| --- | --- |
| 压力 | MPa |
| 流量 | L/min |
| 温度 | ℃ |
| 扭矩 | N·m |
| 振动 | mm/s |

#### 8.8.2 阈值配置

- 按设备类型配置阈值，不按单台设备配置。
- 同一设备类型下的设备共用一套阈值。
- 每个物理量可配置上限和下限。
- 上限和下限至少填写一个。
- 下限不能大于上限。
- 只监控一侧时，另一侧可留空。
- 上下限都留空时，表示该设备类型不监控该物理量。
- 每条阈值可配置报警内容和启用状态。
- 只有管理员可以保存阈值。

#### 8.8.3 设备类型

| 设备类型 | 说明 |
| --- | --- |
| FIVA | 燃油驱动比例阀 |
| PUMP | 液压泵 |
| ICU | 燃油喷射总成 |
| SENSOR | 传感器 |

### 8.9 实时数据

**模块定位**：接收测试台当前运行指标，为实时监控和即时报警提供数据来源。  
**实现逻辑**：系统校验测试台编码，将上报的物理量转换为统一类型，保存最新一帧数据；同一设备同一时间重复上报时覆盖旧数据，后续报警判断读取最新帧。

#### 8.9.1 数据内容

每次实时数据应包含：

- 测试台设备编码。
- 采集时间。
- 压力、流量、温度、扭矩、振动的当前值。
- 急停状态。

规则：

- 采集不到的物理量可以为空。
- 同一测试台、同一时间重复上报时，以最后一次上报覆盖前一次。
- 未知设备编码的数据不得接收。
- 无法识别的物理量应忽略，不影响同一次上报中的其它物理量。

#### 8.9.2 时间要求

- 下位机上报时间默认按本地时间处理。
- 系统比较和判断必须使用统一时间口径。
- 页面展示时按本地时间展示。

#### 8.9.3 数据保留

- 实时数据默认保留 3 个自然月。
- 超过保留期的数据应自动清理。

#### 8.9.4 对接频次

- 当前业务约定下位机约每 2 秒推送一帧实时数据。
- “约 2 秒一帧”是对接约定，当前系统不强制限制上报频率。
- 相同测试台、相同采集时间重复上报时，以最后一次数据为准。
- 具体现场频率如与 2 秒不一致，应在下位机接口协议中明确。

### 8.10 图谱数据

**模块定位**：保存测试过程曲线，供订单复盘、结果分析和后续报告使用。  
**实现逻辑**：系统接收 CSV 和测试参数，先生成处理任务，再解析连续采样点，并根据测试时间匹配订单；处理成功后按订单、采集时间和通道组织图谱。

#### 8.10.1 数据来源

- 图谱数据由下位机在测试结束后上传。
- 每个文件对应一个测试通道。
- 图谱数据属于被测设备，不属于测试台实时运行数据。

#### 8.10.2 上传参数

上传时应至少包含：

- 测试台设备编码。
- 通道类型。
- 文件生成时间。
- 测试开始和结束时间。
- 测试日期。
- 被测设备编码和名称。
- 船名、先导部件序列号和测试人。

#### 8.10.3 文件要求

- 文件格式为 CSV。
- 每行格式为 `index,value`。
- `index` 必须从 0 开始连续递增。
- `value` 必须为有效数字。
- 单文件最多 100 万采样点。
- 文件格式错误时，任务应标记失败并给出原因。

#### 8.10.4 通道类型

支持以下通道：

- 控制给定指令 `CMD`
- 先导驱动反馈 `Drive`
- FIVA 阀反馈 `FivaFB`
- 流量 `Flow`
- 出口工作压力 `FOP`
- 负载压力 `LoadPress`
- 先导反馈 `PilotFB`
- 柱塞反馈 `Plunger`

#### 8.10.5 订单关联

- 系统根据测试时间范围匹配订单。
- 唯一匹配时关联到对应订单。
- 匹配不到或匹配到多个订单时，数据仍可保留，但标记为“未关联订单”。
- 未关联订单数据应在列表中明显提示，供人工核查。

#### 8.10.6 重复上传

- 相同设备、时间和通道的数据重复上传时覆盖旧数据。
- 旧任务应标记为“已替换”。
- 如旧数据已经属于某个订单，且新数据匹配到不同订单，则不允许覆盖。

#### 8.10.7 处理状态

| 状态 | 含义 |
| --- | --- |
| 待处理 | 文件已上传，等待处理 |
| 处理中 | 正在解析文件并生成图谱数据 |
| 成功 | 数据处理完成 |
| 失败 | 处理失败，需要查看原因或重试 |
| 已替换 | 数据已被后续上传替换 |

#### 8.10.8 任务管理

- 管理员可查看全部遥测任务。
- 支持按车间、订单号、文件名、状态、被测设备和时间查询。
- 支持查看任务参数详情。
- 支持预览 CSV 文件。
- 支持失败任务重试。
- 支持单个删除和批量删除。
- 处理中任务不得删除。
- 任务和原始文件默认保留 1095 天。

#### 8.10.9 解析频次

- 系统默认每 5 秒检查一次待处理图谱任务。
- 每轮最多认领 5 个任务进行处理。
- 处理中的任务超过 10 分钟仍未完成时，视为异常中断并恢复为待处理。
- 异常中断恢复后，默认等待 30 秒再重新处理。
- 处理失败的任务按指数退避重试，单次等待最长 60 分钟。

### 8.11 报警管理

**模块定位**：及时发现测试台超限、设备异常和通信中断，并向用户展示当前和历史的异常状态。  
**实现逻辑**：系统读取最新实时帧或心跳状态，满足条件时即时创建报警；同一异常保持一条进行中记录；后续恢复正常时关闭报警；所有登录用户查看同一份报警列表。

#### 8.11.1 报警类型

| 类型 | 是否已实现 | 判定说明 |
| --- | --- | --- |
| 阈值报警 | 是 | 实时值超出设备类型对应阈值 |
| 关联报警 | 否 | 由多个物理量按公式换算后判断，当前公式未提供 |
| 设备报警 | 是 | 传感器数值异常或测试台急停 |
| 通信报警 | 是 | 心跳超过 10 秒未更新 |

#### 8.11.2 “即时报警”定义

本需求中的“即时”是指：

- 不需要异常持续 5 分钟、10 分钟或 20 分钟。
- 不需要人工确认后才成立。
- 最新数据满足异常条件即成立。
- 系统检测周期为 10 秒，因此从异常发生到报警成立最长约 10 秒。
- 数据恢复正常后，下一轮检测即恢复报警。

#### 8.11.3 阈值报警

- 系统读取每台测试台最新一帧实时数据。
- 当前值大于上限或小于下限时，报警成立。
- 当前值回到正常范围时，报警恢复。
- 当前帧没有对应物理量时，保持原报警状态。
- 同一测试台、同一报警类型、同一物理量同时只能存在一条进行中报警。

#### 8.11.4 设备报警

- 所有设备类型发生急停时，产生“测试台急停”设备报警。
- 急停解除后自动恢复。
- `SENSOR` 类型设备数值超出阈值时，除阈值报警外，还应产生设备报警。
- 普通测试台数值超限只产生阈值报警，不重复产生设备报警。

#### 8.11.5 通信报警

- 测试台最后一次心跳超过 10 秒未更新时，产生通信中断报警。
- 从心跳超时到报警被发现，实际时间约为 10～20 秒。
- 心跳恢复后通信报警自动恢复。

#### 8.11.6 恢复规则

- 数据类报警只有在收到后续正常数据后恢复。
- 设备停止上报时，已有报警保持进行中，不自动恢复。
- 通信报警在心跳恢复后恢复。

#### 8.11.7 报警查看

- 所有登录用户可查看全部报警。
- 支持按车间、报警类型、状态和发生时间筛选。
- 页面展示报警类型、测试台、报警内容、发生时间和恢复时间。
- 页面每 10 秒自动刷新。
- 报警不发送站内消息。
- 报警不进行人员派单或升级通知。
- 已恢复报警默认保留 180 天。

---

### 8.12 消息与通告

**模块定位**：提供平台内部的消息、通告、广播和已读管理能力。  
**实现逻辑**：普通消息按接收人保存并推送；通告保存一份主消息，用户已读状态按人记录；用户进入我的消息或我的通告时按本人状态查询。

#### 8.12.1 普通消息

- 管理员可向指定用户发送普通消息。
- 用户可查看自己的消息。
- 支持单条已读和批量已读。
- 支持删除消息。
- 消息分为普通、警告和错误三个级别。

#### 8.12.2 广播通告

- 管理员可发送全员通告。
- 用户可在“我的通告”中查看通告。
- 支持通告已读和删除。
- 管理员端支持发送、查询和删除通告。
- 当前不提供管理员查看某条通告已读/未读人员名单的能力。

#### 8.12.3 实时提醒

- 新普通消息应实时提醒对应接收人。
- 新通告应实时提醒在线用户。
- 右上角消息中心和“我的消息/我的通告”应同步更新。

---

### 8.13 平台管理

**模块定位**：提供业务运行需要的基础配置和日常维护入口。  
**实现逻辑**：管理员分别维护遥测任务、阈值、文件、菜单、布局、数据字典、消息和通告；这些配置被业务页面和业务流程直接使用。

平台管理面向管理员，主要包括：

- 遥测任务管理。
- 阈值管理。
- 文件管理。
- 消息管理。
- 通告管理。
- 菜单管理。
- 布局管理。
- 数据字典管理。

文件管理要求：

- 支持上传、批量上传、查询、下载和删除。
- 文件应可关联到具体业务对象。
- 文件删除后不可恢复。

菜单与布局要求：

- 菜单由管理员统一维护。
- 支持按角色和用户分配菜单。
- 页面布局和菜单属性应可配置。

数据字典要求：

- 支持字典分组和字典项维护。
- 支持静态字典项。
- 业务下拉选项应优先使用统一字典或系统统一配置。

---

### 8.14 系统管理

**模块定位**：维护平台用户、角色、权限、组织和日志，保证业务数据和操作可管、可控、可追溯。  
**实现逻辑**：管理员建立用户和组织，通过角色分配权限；系统按权限控制菜单和操作；关键操作和安全事件分别进入审计日志与安全日志。

系统管理面向管理员，主要包括：

- 用户管理。
- 角色管理。
- 权限配置。
- 组织机构管理。
- 租户管理。
- 审计日志。
- 安全日志。

用户管理：

- 支持新增、编辑、删除用户。
- 支持重置密码、锁定和解锁用户。
- 支持分配角色和组织机构。

角色管理：

- 支持新增、编辑、删除角色。
- 支持为角色分配权限和菜单。

组织机构：

- 支持树形展示、新增、编辑、移动和删除。
- 支持为组织分配用户和角色。

日志管理：

- 审计日志记录业务操作和实体变更。
- 安全日志记录登录等安全事件。
- 审计日志和安全日志默认保留 365 天。

## 9. 关键业务规则汇总

### 9.1 时间规则

- 下位机上报的测试时间按本地时间理解。
- 订单测试开始和结束时间以系统执行操作时的时间为准。
- 实时监控、报警和页面展示使用统一的本地时间口径。
- 系统内部数据清理按保留天数或自然月计算。

### 9.2 数据归属规则

- 设备必须属于一个车间。
- 订单通过测试台间接归属车间。
- 实时数据归属测试台。
- 图谱数据归属测试台和被测设备。
- 报警主体是测试台，不是被测设备。

### 9.3 唯一性规则

- 设备编码在租户内唯一。
- 订单号在租户内唯一。
- 同一测试台同时只能有一个测试中订单。
- 同一测试台、同一报警类型、同一物理量同时只能有一个进行中报警。
- 同一设备、同一时间、同一通道的图谱数据只保留一份。

### 9.4 状态规则

- 订单状态只能按既定流程流转。
- 测试报告状态只能按未获取、获取中、已就绪、失败、过期的定义流转。
- 审核通过后订单锁定。
- 审核不通过允许重新审核。

### 9.5 通知规则

- 订单创建通知车间主管和大区负责人。
- 普通消息通知指定接收人。
- 通告通知全部用户。
- 报警不发送人员通知。
- 报警不做升级、派单和恢复通知。

### 9.6 数据保留规则

| 数据 | 默认保留期 |
| --- | --- |
| 遥测任务和原始文件 | 1095 天 |
| 图谱数据 | 1095 天 |
| 测试报告 | 1095 天 |
| 实时数据 | 3 个自然月 |
| 审计日志 | 365 天 |
| 安全日志 | 365 天 |
| 已恢复报警 | 180 天 |

### 9.7 业务频次与时间规则汇总

| 业务场景 | 周期或阈值 | 是否由系统强制 | 说明 |
| --- | ---: | --- | --- |
| 下位机实时数据上报 | 约 2 秒/帧 | 否 | 当前对接约定，系统不限频；现场需按接口协议执行 |
| 设备心跳超时判定 | 10 秒 | 是 | 超过 10 秒未收到心跳即判定通信中断 |
| 阈值与设备报警检测 | 10 秒/轮 | 是 | 读取每台测试台最新一帧，异常即时成立 |
| 通信报警检测 | 10 秒/轮 | 是 | 结合 10 秒心跳超时，实际发现约需 10～20 秒 |
| 报警页面刷新 | 10 秒 | 是 | 页面自动刷新报警列表 |
| 实时监控页面刷新 | 默认 60 秒 | 是 | 页面最小刷新周期为 30 秒 |
| 图谱任务扫描 | 5 秒/轮 | 是 | 每轮最多处理 5 个待处理任务 |
| 图谱任务卡死恢复 | 10 分钟 | 是 | 处理中超过 10 分钟视为卡死 |
| 图谱卡死任务重试等待 | 30 秒 | 是 | 恢复为待处理后再等待 30 秒 |
| 图谱失败任务重试 | 指数退避，最长 60 分钟 | 是 | 失败次数越多等待越久 |
| 遥测任务和文件清理 | 60 分钟/轮 | 是 | 清理已到期任务和文件以及过期图谱数据 |
| 实时数据清理 | 60 分钟/轮 | 是 | 清理 3 个自然月以前的完整时间数据 |
| 测试报告自动获取检查 | 60 秒/轮 | 是 | 当前功能未完成，数值为预留配置 |
| 测试报告失败重试 | 300～3600 秒 | 是 | 首次 300 秒，之后指数退避；当前功能未完成 |
| 测试报告最大尝试次数 | 60 次 | 是 | 当前功能未完成 |
| 测试报告自动获取期限 | 测试结束后 30 天 | 是 | 超过期限不再自动获取；当前功能未完成 |
| 测试报告清理 | 60 分钟/轮 | 是 | 清理超过 1095 天的报告 |
| 审计日志、安全日志和已恢复报警清理 | 24 小时/轮 | 是 | 按各自保留天数清理 |
| 消息和通告提醒 | 事件触发 | 是 | 新消息发送后实时提醒在线用户，不是定时轮询 |
| 工作台天气刷新 | 60 分钟 | 是 | 支持手动刷新 |

## 10. 异常与边界场景

### 10.1 订单

- 测试台已被其它测试中订单占用时，不允许开始新订单。
- 订单结束时间早于开始时间时，不允许提交。
- 测试报告未就绪时，不允许审核。
- 订单不存在或当前用户无权限时，不允许访问订单详情。
- 审核通过后再次提交审核时，应拒绝操作。

### 10.2 设备

- 设备编码重复时，应提示编码已存在。
- 设备编码创建后修改时，应拒绝修改。
- 用户访问无权限车间设备时，应提示无权访问。
- 心跳超时的设备应产生通信报警并显示为非在线。

### 10.3 图谱数据

- CSV 格式错误时，任务失败并展示具体行号和错误原因。
- 同一时间、设备、通道重复上传时，按覆盖规则处理。
- 无法匹配订单时允许保留数据，但必须标记未关联订单。
- 正在处理的任务不能删除。

### 10.4 报警

- 报警内容变化时应更新当前报警内容，不重复创建新报警。
- 同一异常持续存在时，不重复创建多条报警。
- 数据停止上报时，不自动恢复数据类报警。
- 通信恢复后，自动恢复通信报警。

### 10.5 消息

- 接收人不存在时，消息发送失败。
- 空标题或空内容不允许发送。
- 已读操作应只影响当前接收人的状态。
- 通告当前没有管理员侧已读人员名单。

## 11. 非功能业务要求

本部分只描述业务层面的质量要求，不描述技术实现。

### 11.1 即时性

- 异常报警应在下一轮检测中成立，最长不超过约 10 秒。
- 分析页面应按明确周期刷新，当前默认 60 秒。
- 消息和通告应支持秒级在线提醒。

### 11.2 数据完整性

- 关键业务操作必须记录操作人、操作时间和变更结果。
- 文件、任务和业务对象之间必须保持可追溯关系。
- 删除、覆盖、重试和过期清理必须有明确规则。

### 11.3 安全与权限

- 用户只能访问授权范围内的数据。
- 列表页面和直接访问详情页面必须使用同一权限规则。
- 关键操作必须校验角色和数据范围。
- 文件下载必须校验业务对象访问权限。

### 11.4 可追溯性

- 订单审核记录只追加，不覆盖历史。
- 报告获取过程应保留请求记录。
- 遥测任务失败应保留错误原因。
- 审计日志可查看业务操作和实体变更。
