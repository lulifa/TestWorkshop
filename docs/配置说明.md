# 服务端配置说明

配置文件位置：

```text
aspnet-core/services/TestWorkshop.HttpApi.Host/appsettings.json
```

JSON 文件不支持注释，因此所有配置字段统一记录在这里。修改配置后需要重启后端服务才能生效。

## WorkshopTelemetry

遥测任务处理、订单匹配和文件保留配置。

| 字段 | 单位 | 默认值 | 含义 |
| --- | --- | ---: | --- |
| `RetentionDays` | 天 | `1095` | 遥测任务记录和原始 CSV `FileObject` 的保留时间。过期后由清理 Worker 删除任务记录和文件，不删除 TimescaleDB 中已经解析的遥测数据。 |
| `FileCleanupIntervalMinutes` | 分钟 | `60` | 遥测过期任务和文件的清理执行间隔。 |
| `OrderMatchToleranceSeconds` | 秒 | `0` | 文件时间与订单测试开始、结束时间匹配时允许的容差。`0` 表示严格匹配，不向订单时间两侧扩展。 |

## WorkshopAlarm

报警判定和运行时长统计配置。

| 字段 | 单位 | 默认值 | 含义 |
| --- | --- | ---: | --- |
| `CheckIntervalSeconds` | 秒 | `10` | 阈值报警和设备报警的扫描间隔。每轮读取设备最新实时帧并判断上下限。 |
| `CommunicationTimeoutSeconds` | 秒 | `10` | 设备超过该时间没有心跳时产生通信报警；心跳恢复后自动恢复报警。 |
| `RuntimeGapToleranceSeconds` | 秒 | `6` | 两条相邻心跳间隔不超过该值时，间隔时间才计入设备累计运行时长。 |

## DataRetention

审计日志、安全日志和已恢复报警的统一清理配置。

| 字段 | 单位 | 默认值 | 含义 |
| --- | --- | ---: | --- |
| `CleanupIntervalHours` | 小时 | `24` | 统一清理 Worker 的执行间隔。 |
| `CleanupBatchSize` | 条 | `1000` | 每批查询并直接删除的最大记录数。三类数据共用该值，避免一次删除过多记录造成长事务和锁表。 |
| `AuditLogDays` | 天 | `365` | 审计日志保留时间，超过后直接删除。 |
| `SecurityLogDays` | 天 | `365` | 安全日志保留时间，超过后直接删除。 |
| `ClearedAlarmDays` | 天 | `180` | 已恢复报警的保留时间，超过后直接删除。只处理 `Status=Cleared` 的记录，活动报警不会删除。 |

清理规则：

- 删除是不可恢复的物理删除。
- 每个清理任务单独捕获异常，一个任务失败不会阻塞其他任务。
- 活动报警表示当前仍在发生的故障，会一直保留，直到报警恢复。

## WorkshopTestReport

外部测试报告自动获取、重试和文件限制配置。

| 字段 | 单位 | 默认值 | 含义 |
| --- | --- | ---: | --- |
| `Enabled` | 布尔 | `false` | 是否启用测试报告自动获取和手动拉取。接口未配置时保持 `false`。 |
| `UseMock` | 布尔 | `false` | 是否使用内置模拟报告适配器，仅用于外部接口未完成时联调。 |
| `PollingIntervalSeconds` | 秒 | `60` | 测试报告获取 Worker 的扫描间隔。 |
| `MinRetryDelaySeconds` | 秒 | `300` | 首次重试等待时间。后续按指数退避增长。 |
| `MaxRetryDelaySeconds` | 秒 | `3600` | 单次重试等待时间的上限。 |
| `MaxAttempts` | 次 | `60` | 同一订单报告获取的最大尝试次数。 |
| `MaxFetchDaysAfterTest` | 天 | `30` | 订单测试结束超过该天数后，不再自动获取测试报告。 |
| `MaxFileSizeBytes` | 字节 | `209715200` | 单个报告文件允许的最大大小，默认约 `200 MB`。 |
| `StaleProcessingMinutes` | 分钟 | `10` | 获取记录停留在处理中状态超过该时间后，视为卡死并允许重新处理。 |
| `BatchSize` | 条 | `5` | Worker 每轮最多处理的订单数量。 |

重试时间计算方式：

```text
第 1 次：MinRetryDelaySeconds
第 2 次：MinRetryDelaySeconds × 2
第 3 次：MinRetryDelaySeconds × 4
...
最大不超过 MaxRetryDelaySeconds
```

## 推荐生产配置

当前默认值适合大多数内部部署场景：

```json
{
  "WorkshopTelemetry": {
    "RetentionDays": 1095,
    "FileCleanupIntervalMinutes": 60,
    "OrderMatchToleranceSeconds": 0
  },
  "WorkshopAlarm": {
    "CheckIntervalSeconds": 10,
    "CommunicationTimeoutSeconds": 10,
    "RuntimeGapToleranceSeconds": 6
  },
  "DataRetention": {
    "CleanupIntervalHours": 24,
    "CleanupBatchSize": 1000,
    "AuditLogDays": 365,
    "SecurityLogDays": 365,
    "ClearedAlarmDays": 180
  },
  "WorkshopTestReport": {
    "Enabled": true,
    "UseMock": false,
    "PollingIntervalSeconds": 60,
    "MinRetryDelaySeconds": 300,
    "MaxRetryDelaySeconds": 3600,
    "MaxAttempts": 60,
    "MaxFetchDaysAfterTest": 30,
    "MaxFileSizeBytes": 209715200,
    "StaleProcessingMinutes": 10,
    "BatchSize": 5
  }
}
```

生产环境启用真实报告接口时，将 `WorkshopTestReport:Enabled` 设为 `true`，并确认 `UseMock` 为 `false`。
